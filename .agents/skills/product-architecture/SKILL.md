# Product Architecture Skill

1. Read the product brief, requirements, architecture and evaluation alignment matrix.
2. Restate the user problem and the defensive benefit of the proposed work.
3. Map each proposed feature to a named threat and a measurable acceptance criterion.
4. Prefer the smallest complete feature that improves protection and awareness.
5. Identify data flows, trust boundaries, dependencies and failure modes before selecting a design.
6. Reject scope that requires storing sensitive input or contacting suspicious links unless a reviewed requirement demands it.
7. Record material choices and trade-offs in `DECISIONS.md`.
8. Produce an implementation sequence, test evidence and exit gate before coding.
9. Do not invent official evaluation weights or promise a score.
